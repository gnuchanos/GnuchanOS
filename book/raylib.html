Window and the frame loop

The Raylib module is loaded with #native . Every program has the same skeleton: open a window, run a loop, close it. InitWindow takes the size and the title; WindowShouldClose returns 1 when the user clicks the X or presses Escape, so the loop condition is negated.

raylib.gcsf
#native 

int main() {
    Raylib.InitWindow(800, 600, "GCL Raylib");
    Raylib.SetTargetFPS(60);

    while (!Raylib.WindowShouldClose()) {
        Raylib.BeginDrawing();
        Raylib.ClearBackground(Raylib.RAYWHITE);

        # everything you draw goes between these two calls
        Raylib.DrawText("Hello from GCL", 20, 20, 30, Raylib.BLACK);

        Raylib.EndDrawing();
    }

    Raylib.CloseWindow();
    return 0;
}

Colors

A color is a 32-bit integer with the channels packed into it, so it is a plain value you can store, pass and return. All the standard raylib colours are constants on the module.

Input

Input calls all return 1 or 0. IsKeyDown is true for as long as the key is held; IsKeyPressed is true only on the frame it went down, which is what you want for one-shot actions such as jumping or shooting.

input.gcsf
if (Raylib.IsKeyDown(Raylib.KEY_W)) {
    # held down: keep walking
}

if (Raylib.IsKeyPressed(Raylib.KEY_SPACE)) {
    # pressed this frame: jump once
}

int mx = Raylib.GetMouseX();
int my = Raylib.GetMouseY();

if (Raylib.IsMouseButtonPressed(Raylib.MOUSE_BUTTON_LEFT)) {
    Raylib.DrawCircle(mx, my, 10, Raylib.RED);
}

Audio

Sounds are short and loaded whole; music streams from disk. Both need InitAudioDevice before the first load and CloseAudioDevice at the end. Every frame must call UpdateMusicStream for the tracks that are playing — skip it and the music goes quiet after one buffer.

Raylib.Sound hit = Raylib.LoadSound("hit.wav");

Raylib.PlayMusicStream(theme);

    Raylib.UpdateMusicStream(theme);   # required every frame

    if (Raylib.IsKeyPressed(Raylib.KEY_SPACE)) {

}

RaylibFPS — the player

The module owns the walk camera. Declare an FPS, place it, then call the two methods that move it: Move() reads the keyboard and Look() reads the mouse. Height is the eye height above the player's feet.

RaylibSimpleMesh — terrain and props

TerrainLoad(obj) loads a level and returns a handle whose fields you set: a texture and a tint colour. LoadObj(file) does the same for a single prop. Both are drawn with Draw() from inside BeginMode3D.

Terrain and Mesh are the same operation underneath: load a file as a raylib Model and keep it in this module's registry. The returned number is the registry index, and that is what the struct's handle leaf stores. There is deliberately one registry and one Draw() path, so a Terrain and a Mesh behave identically and neither drifts from the other.

Placement uses Position, Rotate and Scale; rotation is in degrees. Always pair a load with its unload at the end of the program.

mesh.gcsf

RaylibSimpleCollision — standing and sliding

Two calls do the whole job. TerrainCollision(player, terrain) finds the ground height under the player and keeps them standing on it. MoveAndSlide(player, dx, dy, dz, iterations, mesh) resolves overlap against solid meshes and slides along whatever was hit — the same idea as Godot's move_and_slide().

The player is treated as a capsule: Height tall and a small radius. The first three arguments are a movement vector; because the player module has already moved the player this frame, the demo passes 0, 0, 0 and lets the call perform only the resolution step.

collision.gcsf
PLAYER.Move();
PLAYER.Look();

# Ground: keep the player on the terrain.
RaylibSimpleCollision.TerrainCollision(PLAYER, Terrain);

# Solid objects: push out of the crate and slide along it.
RaylibSimpleCollision.MoveAndSlide(PLAYER, 0, 0, 0, 4, CUBE);
MemberMeaning
TerrainCollision(player, terrain)Ground clamp against the terrain mesh.
MoveAndSlide(player, dx, dy, dz, iterations, mesh)Resolve overlap and slide along the mesh.
iterationsHow many resolution passes to run; 4 is plenty.
ℹ️

Order matters: move and look first, then collide. Resolving before the player has moved would test last frame's position.

RaylibShader — your own fragment shader

CreateSimpleShader(vs, fs, version) loads a vertex/fragment pair and returns a handle. The files are looked up in assets/; a file that does not already start with #version gets the version you pass prepended to it.

The module exists because DrawModel does not honour BeginShaderMode by itself: it always draws with the shader stored in the model's material. The mesh module therefore asks which shader the script selected before drawing, which is what makes the block below actually take effect.

shader_module.gcsf
RaylibShader.SimpleShader shader =
    RaylibShader.CreateSimpleShader("lighting.vs", "lighting.fs",
                                    Raylib.GLSL_VERSION);

Raylib.BeginShaderMode(shader);
    Terrain.Draw();   # drawn with lighting.fs
    water.Draw();
    CUBE.Draw();
Raylib.EndShaderMode();
MemberMeaning
CreateSimpleShader(vs, fs, glslVersion)Load a shader pair; returns a handle.
HandleThe shader handle, for read-back.
💡

Everything that must be lit or fogged goes inside the block. Anything drawn outside it uses the default shader — which is exactly how the light glow cubes stay unfogged.

RaylibSimpleLight — sun and point lights

One struct serves both light kinds and the module tells them apart by handle range: suns are 0..SUN_MAX-1, point lights start at 1000. A sun uses Rotate (a direction, in degrees); a point light uses Position.

Update() is the part that matters: it writes the light into the shader's uniforms. Until it is called, setting Position.x changes a variable in the interpreter and nothing on screen. Draw() is pure visualisation — a glowing cube marking where the light is — and must be called inside BeginMode3D.

lights.gcsf
RaylibSimpleLight.SunLight SUN = RaylibSimpleLight.CreateSun(Raylib.WHITE);
SUN.Rotate.x = 0;
SUN.Rotate.z = 90;   # elevation: 90 = straight overhead
SUN.Rotate.y = 0;

# CreatePointLight(color, sun, x, y, z)
RaylibSimpleLight.SunLight lamp =
    RaylibSimpleLight.CreatePointLight(Raylib.YELLOW, SUN, 15, -1, -4);

while (!Raylib.WindowShouldClose()) {
    SUN.Update();      # push the sun into the shader
    lamp.Update();     # push the point light into the shader

    Raylib.BeginMode3D(PLAYER.Camera);
        Terrain.Draw();
        lamp.Draw();   # glowing cube, so you can find it
    Raylib.EndMode3D();
}
MemberMeaning
CreateSun(color)Directional light; returns a handle.
CreatePointLight(color, sun, x, y, z)Point light at a position.
HandleThe light's id: 0.. for suns, 1000+ for point lights.
Position.x / .y / .zPoint light position.
Rotate.x / .y / .zSun direction, in degrees.
SunOptional sun a point light is balanced against.

⚠️

Lights share the shader's lights[] array with the sun. The slot limit is one number that must stay identical in three places — the shader source, gcl_raylib.c and the light module. Raise one and not the others and the extra light is dropped silently.

The demo also gives the player a light that follows them: a point light whose Position is copied from PLAYER.Position every frame, then updated.

RaylibSkybox — sky, sun and clouds

CreateSimpleSkybox() draws the whole sky from one fragment shader — gradient, sun/moon disc, banded clouds and stars. Because it is a separate GL program, fog uniforms never reach it: the sky stays crisp while the terrain fades, which is the entire point of doing fog in the terrain shader.

Update() advances the day cycle and, more importantly, is the source of truth for the lighting module: RaylibSimpleLight asks the skybox for the sun's direction, colour and power. There is only ever one sun definition in the process.

The sky dome is recentred on the camera every frame, so the horizon stays put no matter how far the player walks.

sky.gcsf
RaylibSKYBOX.Skybox sky = RaylibSKYBOX.CreateSimpleSkybox();
sky.DailyCycle = RaylibSKYBOX.night;  # night / day / morning / noon ...
sky.cloudON    = true;
sky.CloudSpeed = 0.05;

while (!Raylib.WindowShouldClose()) {
    sky.Update();

    Raylib.BeginMode3D(PLAYER.Camera);
        sky.Draw();   # needs no extra shader
    Raylib.EndMode3D();
}
MemberMeaning

TimePosition in the cycle.
DayLengthHow long one full cycle lasts.
CloudAmountCloud coverage.
CloudSpeedCloud drift speed.
CloudONAdds an extra cloud layer on top of the soft clouds.
StarAmountStar density at night.
SunSize / SunBrightnessDisc size and brightness.
CycleCountHow many full cycles have elapsed.

💡

DailyCycle just sets Time for you. Animating Time yourself gives a moving sun, and the lights follow it automatically because they read the sun from here.

RaylibFOG — distance fog

This module draws nothing at all. It only fills the fogColor, fogParams and fogShape uniforms of the shader the scene is already being drawn with, and the terrain's own fragment shader mixes each pixel towards the fog colour by its real distance from the eye.

That is what separates it from a grey curtain: the effect follows true depth, so it is a smooth gradient instead of a hard edge, and the sky is untouched because it is a different program.

fog.gcsf
# CreateFog(color, density, start, end, enabled, heightFog)
RaylibFOG.FOG fogy =
    RaylibFOG.CreateFog(Raylib.SKYBLUE, 0.25f, 10.0f, 45.0f, true, true);

fogy.Mode = RaylibFOG.ExponentialSquared;
fogy.HeightFog = true;
fogy.Height  = 30.0f;   # height fog ceiling
fogy.Falloff = 0.5f;    # softness of the fade

# inside BeginShaderMode, together with the terrain and the water:
fogy.Update();
MemberMeaning
CreateFog(color, density, start, end, enabled, heightFog)Build a fog value.
ColorFog colour.
DensityHow thick the fog gets.
Start / EndNear and far edge of the fog band, in world units.
ModeLinear, Exponential or ExponentialSquared.
HeightFog / Height / FalloffFog that settles below a ceiling, and how softly it fades out.
EnabledMaster switch.
Update()Writes the uniforms.
⚠️

Update() belongs inside the BeginShaderMode block. Outside it there is no way to know which program is being targeted, and the fog simply does not apply — the call succeeds and nothing changes on screen.

Height fog is what stops the whole world reading as a flat grey wall: hills below the ceiling stay clearer, hollows fill up first.

RaylibSimpleWater — water that knows about swimming

The module is geometry only: a surface and a bed loaded from an OBJ, animated with waves in the vertex stage and rendered with its own shader. Whether you are swimming, and the thresholds involved, live in the player module (RaylibFPS) — so the moment the screen says "swimming" and the moment the physics swims can never drift apart.

Reflection and sun values are read from the skybox, and the fog values from the shared fog state, so water sits in exactly the same world as the terrain rather than looking like glass laid over it.

water.gcsf
RaylibSimpleWater.Water water =
    RaylibSimpleWater.CreateSimpleWaterFromOBJ("water.obj");

water.WaveStrength = 0.2f;
water.WaveSpeed    = 0.5f;
water.WaveScale    = 0.6f;
water.Reflection   = 1.0f;

while (!Raylib.WindowShouldClose()) {
    water.Update();   # advances the waves, refreshes uniforms

    Raylib.BeginMode3D(PLAYER.Camera);
        water.Draw();
    Raylib.EndMode3D();

    # 2D overlay: only active when the eyes are under the surface.
    water.DrawUnderwaterEffect();
}
