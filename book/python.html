Python

Run a Python script from a GCL program, share values with it, and draw with the raylib bindings that ship with the runtime.

Python from GCL

GCL can host a Python interpreter the same way it hosts raylib: as a module. Load #native , start the runtime, and from then on the two languages share one process. GCL keeps driving the window and the frame loop; Python does whatever you would rather write in Python.

ℹ️

The interpreter runs on its own thread. Both sides keep working at once, which is the point — but it also means the two must not touch the same variable at the same moment.

Starting the runtime

Embed.Run starts it and returns once the interpreter is up. Embed.IsActive tells you whether it is still running, and Embed.Stop shuts it down. Always stop it before the program ends.

start.gcsf
#native 

Embed.Run(type="python");

if (Embed.IsActive(type="python")) {
    Stdio.printf("python is up\n");
}

Embed.Stop(type="python");
MethodDescription
Embed.Run(type="python")Start the interpreter and load the script.
Embed.IsActive(type="python")1 while it is running.
Embed.Stop(type="python")Shut it down and join the thread.

Which file gets loaded follows the project: the entry sits next to the .gcsf file. A project that keeps its Python in scripts/ loads it from there.

Moving values across

Embed.SendValue writes a variable into the Python namespace, and Embed.GetValue reads one back out. The name has to be a plain global on the Python side — anything inside a function or a class is not reachable. Values travel as int, float and char.

values.gcsf
Embed.SendValue(type="python", name="hp",    value="100");
Embed.SendValue(type="python", name="speed", value="2.5");

# Python has had a frame or two to run by now.
int score = Embed.GetValue(type="python", name="score");
game.py
# globals, so GCL can see them
hp = 100
score = 0

def think(dt):
    global score
    score += 1
⚠️

Two things break this quietly. A variable defined inside a function is not a global, so GetValue returns nothing; and reading a variable GCL has not written yet gives you whatever Python last put there, which may be stale. Give the Python side a sane default at the top of the file.

💡

Because both run at once, a value read mid-frame can be one frame behind. For anything the renderer depends on, treat the Python number as input to the next frame rather than as a value that must be exact this frame.

ℹ️

All bindings use the same constant names. In Python the prefix is usually raylib. or rl., so Raylib.KEY_W becomes raylib.KEY_W or rl.KEY_W depending on the import.

raylib from Python

The runtime ships with raylib bindings, so a Python script can open its own window and draw without GCL's help. That is the other way to use the two together: instead of GCL driving, Python drives and GCL supplies the game logic and the shared state.

window.py
import raylib as rl

rl.InitWindow(800, 600, "from Python")
rl.SetTargetFPS(60)

while not rl.WindowShouldClose():
    rl.BeginDrawing()
    rl.ClearBackground(rl.RAYWHITE)
    rl.DrawText("hello", 20, 20, 30, rl.BLACK)
    rl.EndDrawing()

rl.CloseWindow()
PythonMatches
rl.InitWindow(w, h, title)Raylib.InitWindow
rl.BeginDrawing() / rl.EndDrawing()Same frame pair as GCL.
rl.DrawText(text, x, y, size, color)Raylib.DrawText.
rl.RAYWHITE, rl.BLACK, ...The same colour constants.
⚠️

Only one of the two may own the window. If GCL already called InitWindow, a Python script must not call it again — raylib has a single global context and the second call is at best ignored and at worst crashes. Pick one side to be the host.

A complete example

GCL keeps the frame loop and the input, Python keeps the game rules. Each frame GCL hands over the state it knows, asks Python to think, and reads the answer back.

main.gcsf
#native 
#native 

int main() {
    Raylib.InitWindow(800, 600, "GCL + Python");
    Raylib.SetTargetFPS(60);
    Embed.Run(type="python");

    while (!Raylib.WindowShouldClose()) {
        Embed.SendValue(type="python", name="dt", value="0.016");

        int x = Embed.GetValue(type="python", name="x");

        Raylib.BeginDrawing();
        Raylib.ClearBackground(Raylib.RAYWHITE);
        Raylib.DrawCircle(x, 300, 20, Raylib.BLUE);
        Raylib.EndDrawing();
    }

    Embed.Stop(type="python");
    Raylib.CloseWindow();
    return 0;
}
game.py
dt = 0.016
x  = 400

def step():
    global x
    x += 60 * dt
    if x > 780:
        x = 20
💡

This is the whole pattern: the host owns the window and the frame, the other language owns the rules, and a small set of named globals is the contract between them. Keep that list short and written down.

Runtime patterns that keep working

Once the Python runtime is alive, the important idea is simple: GCL is the host, Python is the worker. The host can own the window and still hand control to the script for AI, logic, networking, or data processing. The contract is a small set of globals and a single shared frame loop.

pattern.py
import raylib as rl

# shared state visible to GCLp = 0
score = 0

def think(dt):
    global p, score
    p += 60 * dt
    score += 1

    if p > 780:
        p = 20

while not rl.WindowShouldClose():
    rl.BeginDrawing()
    rl.ClearBackground(rl.RAYWHITE)
    rl.DrawCircle(p, 300, 20, rl.BLUE)
    rl.EndDrawing()
PatternWhy it matters
Keep shared values at module scopeGCL can read them only when they are globals.
Use a single owner for the windowraylib is a global context; do not re-init it from both sides.
Read the new value next framePython and GCL run concurrently, so frame timing is not perfectly synchronous.
Keep the interface smallFew globals are easier to debug than a big shared table.
⚠️

If you write inside a function and then expect GCL to read it, the value is not a module global. Every shared value must live at the outer level, not under a local function scope.

Input and key checks in Python

The Python binding follows the same raylib key names as GCL, but with the Python module namespace in front. This is the most common expression pattern in Python:

input.py
import raylib as rl

if rl.IsKeyDown(rl.KEY_W):
    x += 1

if rl.IsKeyPressed(rl.KEY_SPACE):
    jump = 1

if rl.IsMouseButtonPressed(rl.MOUSE_BUTTON_LEFT):
    shoot = 1

mx = rl.GetMouseX()
my = rl.GetMouseY()
Python callMeaning
rl.IsKeyDown(rl.KEY_W)True while W is held.
rl.IsKeyPressed(rl.KEY_SPACE)True only on the frame it was pressed.
rl.IsMouseButtonPressed(rl.MOUSE_BUTTON_LEFT)One-shot click check.
rl.GetMouseX()X position of the cursor.
rl.GetMouseY()Y position of the cursor.
rl.GetKeyPressed()Last key typed, useful for text entry.
💡

The exact same names are used in all languages. For Python you usually write rl.KEY_W or raylib.KEY_W, depending on your import. The difference is the prefix, not the constant name itself.
