Lua

An in-process Lua 5.4 runtime, a raylib and a raygui module, and a gcl module to talk to the rest of the program.

Lua inside GCL

GCL loads the Lua runtime the way it loads any other module. From then on there is one process with two languages in it: GCL keeps whatever you wrote in GCL, and Lua runs a real Lua 5.4 program on its own thread. Three globals are created before your script runs:

GlobalWhat it is
raylibThe raylib binding: window, drawing, input, shapes, textures, text, 3D, audio.
rayguiThe raygui binding: widgets, on top of raylib.
gclThe shared store and the runtime handshake.

Function names are the C names, unchanged and in CamelCase: raylib.InitWindow, raylib.DrawCircleV. There is no prefix of your own to add and no wrapper module to import — the tables are already global.

ℹ️

Your script is loaded as a file by the host, so it runs top to bottom like any Lua program. It usually ends in its own frame loop and its own raylib.CloseWindow().

Starting the runtime

From the GCL side, Embed starts and stops the Lua runtime.

host.gcsf
#native 

Embed.Run(type="lua");

if (Embed.IsActive(type="lua")) {
    Stdio.printf("lua is up\n");
}

Embed.Stop(type="lua");
MethodDescription
Embed.Run(type="lua")Start Lua and load the script.
Embed.IsActive(type="lua")1 while it is running.
Embed.Stop(type="lua")Shut it down and join the thread.

The script the runtime loads follows the project layout: an entry next to the .gcsf file, or in scripts/ when the project keeps its scripts there.

Shared state

This is the part that matters and the part that is easiest to get wrong. The Lua script does not read GCL variables directly. Both sides meet in a small shared store, and each value is a number under a string key.

state.lua
gcl.init()

gcl.set_state("paddle_y", 300)

local ball_x = gcl.get_state("ball_x")
if type(ball_x) ~= "number" then
    ball_x = 400          -- the key has not been written yet
end
FunctionReturnsDescription
gcl.init()-Handshake with the host. Call it once, first.
gcl.set_state(key, value)-Write a number under a string key.
gcl.get_state(key)number or nilRead it back. nil when the key has never been written.
⚠️

get_state returns nil for a key that does not exist yet, not 0. Arithmetic on that nil stops your script at the line where it happens, which is why every read in the demo goes through a helper with a fallback.

The store is shared across the whole program, not just this one script. The demo project examples/demo_pong_lua_vs_python runs the Lua court and the Python court side by side, and the ball is a single pair of keys they both read.

raylib module

The full binding, grouped the way raylib groups it. Everything is raylib.Name(args). Functions that return a value in C return it here; functions that return void return nothing. A C bool arrives as a Lua true/false.

window.lua
raylib.InitWindow(800, 600, "from Lua")
raylib.SetTargetFPS(60)

while not raylib.WindowShouldClose() do
    raylib.BeginDrawing()
    raylib.ClearBackground(raylib.RAYWHITE)
    raylib.DrawText("hello", 20, 20, 30, raylib.BLACK)
    raylib.EndDrawing()
end

raylib.CloseWindow()

raygui module

Widgets are raygui.GuiName(rect, ...). The rectangle is built with raylib.Rectangle and passed explicitly as the first argument — there is no implicit "last rectangle" state across the two tables, so each widget carries its own layout.

gui.lua
raylib.Rectangle(20, 20, 200, 40)   -- built inline, one per widget
if raygui.GuiButton(raylib.Rectangle(20, 20, 200, 40), "Reset") then
    width = 200
end

width = raygui.GuiSlider(raylib.Rectangle(20, 80, 300, 30),
                      "", "Width", width, 50.0, 500.0)

Complete example

A window with a paddle, driven by shared state and drawn with the bindings above. This is the shape of the Lua half of the pong demo.

court.lua
gcl.init()

local W, H     = 800, 600
local PADDLE_H = 96
local SPEED    = 470

-- read a shared number, with a fallback for the first frames
local function get(key, fallback)
    local v = gcl.get_state(key)
    if type(v) ~= "number" then return fallback end
    return v
end

local function clamp(v, lo, hi)
    if v < lo then return lo end
    if v > hi then return hi end
    return v
end

raylib.InitWindow(W, H, "Lua court")
raylib.SetTargetFPS(60)

local accent  = raylib.Color(102, 178, 255, 255)
local court   = raylib.Color(0, 0, 102, 255)
local paddle_y = H / 2

gcl.set_state("paddle_y", paddle_y)

while not raylib.WindowShouldClose() do
    local dt -- seconds this frame took
    dt = raylib.GetFrameTime()
    if dt > 0.05 then dt = 0.05 end

    local ball_y = get("ball_y", H / 2)

    -- walk toward the ball, one step at a time
    local step = SPEED * dt
    paddle_y = paddle_y + clamp(ball_y - paddle_y, -step, step)
    paddle_y = clamp(paddle_y, PADDLE_H / 2, H - PADDLE_H / 2)

    gcl.set_state("paddle_y", paddle_y)

    raylib.BeginDrawing()
    raylib.ClearBackground(court)

    raylib.DrawRectangleRounded(
        raylib.Rectangle(36, paddle_y - PADDLE_H / 2, 18, PADDLE_H),
        0.5, 8, accent)

    raylib.DrawCircleV(get("ball_x", W / 2), ball_y,
                         10, raylib.Fade(raylib.WHITE, 0.9))

    raylib.EndDrawing()

    if raylib.IsKeyPressed(raylib.KEY_ESCAPE) then break end
end

raylib.CloseWindow()

The three traps

⚠️

local is not exported. Only globals exist as far as the host is concerned. A shared value written as local score = 0 disappears from the other side without any error at all — which is the worst kind of bug, because the script runs perfectly and the number simply never arrives.

⚠️

A missing key is nil, not 0. gcl.get_state("x") + 1 on the first frame is an arithmetic error. Read through a helper with a fallback, every time.

⚠️

One window per program. raylib has a single global context. If GCL or another script has already called InitWindow, calling it again is at best ignored. Decide which language owns the window before writing either file.

💡

Two smaller ones worth knowing: DrawTriangle only fills when its vertices wind the same way raylib expects, so a mirrored triangle can vanish silently; and raylib.TextFormat is raylib's own formatter, so reach for Lua's string.format unless you specifically want raylib's {} style.
